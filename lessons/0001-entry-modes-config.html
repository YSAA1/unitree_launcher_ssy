0001 - 从入口读懂模式和配置

目标：看到一条 uv run ... 命令后，能预测它会加载哪个配置、选择哪个 robot backend、怎么进入 Runtime。

这节课的单点胜利

把项目入口理解成一个装配器，而不是一个算法文件。

CLI mode
  -> argparse defaults
  -> YAML config
  -> CLI overrides
  -> robot backend
  -> policy/default policy
  -> safety + input + logger
  -> Runtime
  -> runner: GUI / Viser / headless

模式是第一分叉

README 先给出五个模式：sim、eval、real、mirror、replay。源码里的 main.py 也把这五个模式作为 CLI subparser。

Mode 默认配置 关键后端/路径 你应该先问的问题
sim configs/sim.yaml SimRobot 这是 GUI、Viser 还是 headless？有没有 policy？
eval configs/sim.yaml，然后强制 1000 Hz physics SimRobot 这是评估，不是交互调试；步数/时长是什么？
real configs/real.yaml RealRobot 安全、网络接口、手柄急停、prepare gate 是否清楚？
mirror configs/sim.yaml 只读 mirror runner 这是观察真机状态，不应发控制命令。
replay 日志路径驱动 replay runner 这是分析历史数据，不是控制机器人。

速查版见 模式速查表。

配置不是散落的字典

config.py 把 YAML 加载成 dataclass：RobotConfig、PolicyConfig、ControlConfig、SafetyConfig、NetworkConfig、ViewerConfig、LoggingConfig。加载后会验证 robot variant、频率整除、日志格式等。

configs/sim.yaml

默认 g1_29dof，50 Hz policy，500 Hz MuJoCo physics，DDS domain 1。

configs/real.yaml

真机网络默认 eth0，DDS domain 0，开启 tilt/frame-drop 检查。

configs/unsafe.yaml

关闭 tilt check 和 joint position limits。它应该触发安全警觉。

main.py 的正常装配路径

  1. build_parser() 定义五个 mode 和各自默认配置。
  2. main() 先特殊处理 mirror 和 replay，因为它们不是正常 policy 控制路径。
  3. 普通控制路径检查 policy / gantry / zero-torque，再加载 config。
  4. sim/eval 创建 SimRobot；real 创建 RealRobot。
  5. 加载 default policy 和 active policy。
  6. 创建 SafetyController、logger、estimator、input manager。
  7. 创建 Runtime(...)。
  8. 根据 --gui、--viser 或 headless 选择 runner。
风险规则：real 模式不是“把 sim 换个 backend”。它还引入真机网络、无线手柄、prepare phase、硬件后端和真实安全风险。

用测试锁住理解

tests/test_main.py 是这节课的练习册。它验证 sim 默认配置、real 默认 interface、CLI override、policy 格式检测、headless runner 等入口行为。

uv run pytest tests/test_main.py tests/test_config.py -x
