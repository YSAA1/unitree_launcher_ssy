0003 - argparse 和 preset 数据流

目标：看懂 parser、subparser、args、args.preset 和 config 的区别。

一句话模型

argparse 不运行机器人。它只把命令行字符串解析成一个对象：args。真正影响运行的是后面业务代码怎么使用 args。

uv run sim --gui --policy assets/policies/stance_29dof.onnx
          │
          ▼
["sim", "--gui", "--policy", "assets/policies/stance_29dof.onnx"]
          │
          ▼
args.mode = "sim"
args.gui = True
args.policy = "assets/policies/stance_29dof.onnx"
args.config = "configs/sim.yaml"
args.preset = None

parser 和 subparser

parser 是顶层解析器。它先负责知道“这个程序有几个子命令”。

subparser 是每个子命令自己的解析器。sim 有 --gui、--viser；real 有 --interface、--zero；replay 有日志路径。

parser = argparse.ArgumentParser(...)
subparsers = parser.add_subparsers(dest="mode", required=True)

sim_parser = subparsers.add_parser("sim")
real_parser = subparsers.add_parser("real")
replay_parser = subparsers.add_parser("replay")

为什么需要 subparser

因为 sim、real、replay 不是同一种命令。

命令需要的参数不应该出现的参数
sim--gui、--viser、--policy真机 --zero
real--interface、--auto、--zero仿真 GUI 逻辑
replaylog_dir、--speed、--loop--policy

本项目 args.preset 的完整流动

定义位置：main.py:_add_base_args

parser.add_argument("--preset", default=None,
                    help="Named config preset (e.g., unsafe)")

如果你不传：

uv run sim --policy p.onnx

args.preset = None
args.config = "configs/sim.yaml"

main.py:
  config = load_config(args.config)

如果你传：

uv run sim --preset unsafe --policy p.onnx

args.preset = "unsafe"
args.config = "configs/sim.yaml"

main.py:
  preset_path = configs/unsafe.yaml
  config = load_config(preset_path)

configs/unsafe.yaml 只覆盖少量 safety 字段：

safety:
  tilt_check: false
  joint_position_limits: false
注意：preset 是“先加载哪个配置文件”的选择。它不是 policy，不是 mode，也不是 Runtime 状态。

args 和 config 的分工

对象来源作用
args命令行记录用户这次运行传了什么。
configYAML + CLI overrides运行时模块真正使用的配置。
robot/policy/runtime代码构造拿 config 和 args 的具体字段创建对象。
