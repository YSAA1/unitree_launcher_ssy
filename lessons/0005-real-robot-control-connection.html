0005 - 真机怎么连接和控制

目标：理解 uv run real 到底在哪里运行、怎么连接 G1、Python 和 C++ 各自负责什么。

第一件事：代码跑在 G1 onboard PC 上

README 里的真机部署流程是先把代码同步到机器人，再 SSH 到机器人上运行。

./scripts/deploy_to_robot.sh
ssh unitree@192.168.123.164
cd ~/unitree_launcher
uv run real --policy assets/policies/stance_29dof.onnx

所以真机控制的核心不是“开发机远程发电机命令”，而是：

开发机同步代码
  -> 登录 G1 onboard PC
  -> onboard PC 运行 Python
  -> Python 调 C++ binding
  -> C++ 通过 DDS 和电机控制板通信

real 模式从 main.py 进入 RealRobot

real 子命令定义默认配置是 configs/real.yaml，默认网卡是 eth0。

real_parser = subparsers.add_parser("real")
_add_base_args(real_parser, "configs/real.yaml")
real_parser.add_argument("--interface", default="eth0")

进入 robot 创建分支后，sim/eval 用 SimRobot，否则走 RealRobot。

if args.mode in ("sim", "eval"):
    robot = SimRobot(config)
else:
    robot = RealRobot(config)

RealRobot.connect：真正打开连接

RealRobot.connect() 会 import unitree_cpp.UnitreeController。如果没有安装，就提示去跑 scripts/build_cpp_backend.sh。

from unitree_cpp import UnitreeController

config_dict = {
    "net_if": self._iface_name,
    "control_dt": 0.02,
    "msg_type": "hg",
    "control_mode": "position",
    "lowcmd_topic": "rt/lowcmd",
    "lowstate_topic": "rt/lowstate",
    "num_dofs": self._n_dof,
}
self._controller = UnitreeController(config_dict)

这里的重点：

  • net_if 是网卡，比如 G1 onboard 的 eth0。
  • lowstate_topic 是读机器人状态的 DDS topic。
  • lowcmd_topic 是发底层命令的 DDS topic。
  • control_dt=0.02 表示 C++ 层 20ms 周期重发命令，也就是 50 Hz。

状态怎么进 Python

RealRobot.get_state() 调 C++ controller：

state = self._controller.get_robot_state()
ms = state.motor_state

return RobotState(
    joint_positions=np.array(ms.q[:self._n_dof]),
    joint_velocities=np.array(ms.dq[:self._n_dof]),
    joint_torques=np.array(ms.tau_est[:self._n_dof]),
    imu_quaternion=np.array(state.imu_state.quaternion[:4]),
    ...
)

真机没有 MuJoCo 的世界坐标，所以 base_position 和 base_velocity 先填 NaN。如果 policy 需要 base 状态，就要靠 estimator 填。

命令怎么发到真机

Runtime.step() 还是同一条线：

state = robot.get_state()
vel_cmd = input_manager.get_velocity()
cmd = policy.step(state, vel_cmd)
cmd = safety.clamp_command(cmd, state)
robot.send_command(cmd)
robot.step()

但真机里的 robot.send_command(cmd) 是：

self._controller.set_gains(cmd.kp.tolist(), cmd.kd.tolist())
self._controller.step(cmd.joint_positions.tolist())

也就是说 Python 把 RobotCommand 转成 C++ binding 调用；C++ 层负责 DDS、CRC、motor mode 和底层重发。

无线手柄怎么进控制循环

main.py 在 real 模式会把 WirelessInput 放进输入控制器列表，并注册给 robot。

if args.mode == "real":
    wireless = WirelessInput()
    input_controllers.append(wireless)

robot.connect()
robot.set_wireless_handler(wireless.parse)

RealRobot.get_state() 每次读状态时，会拿到 state.wireless_remote，然后调用 wireless.parse(remote)。这样 Start、Stop、A 键 E-stop、摇杆速度命令就进入 Runtime。

prepare/start 为什么存在

真机模式会设置一个 5 秒 PREPARE 序列：

if args.mode == "real":
    runtime._mode_sequence = [(PREPARE, 5.0)]
    if not args.auto:
        runtime.require_manual_start = True

含义：先从当前电机位置平滑过渡到 default stance，然后等待无线手柄 Start。不是一运行就直接 policy 接管。

安全底线：软件 A 键 E-stop 依赖 Python 循环还活着；如果 Python 卡死，C++ 仍可能重发最后命令。硬件 fallback 是无线手柄 L2+B，这个不能省。
