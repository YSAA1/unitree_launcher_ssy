0004 - Runtime 数据契约

目标：看懂一帧控制循环里，状态、策略、命令和机器人后端之间到底传了什么。

先看四个接口，不看具体策略

这节只读四个代码坐标：

  • robot/base.py:63 的 RobotState
  • robot/base.py:97 的 RobotCommand
  • policy/base.py:61 的 Policy.step
  • robot/base.py:122 的 RobotInterface

RobotState：机器人现在是什么样

RobotState 是当前状态快照。它不负责控制，只负责描述当前机器人。

timestamp
joint_positions        # (N_DOF,)
joint_velocities       # (N_DOF,)
joint_torques          # (N_DOF,)
imu_quaternion         # (4,) wxyz
imu_angular_velocity   # (3,)
imu_linear_acceleration# (3,)
base_position          # (3,)
base_velocity          # (3,)
sdk_state              # real/mirror only

测试里对形状有明确断言：tests/test_sim_robot.py 检查 29DOF 时关节数组是 (29,)，IMU 四元数是 (4,)，base 状态是 (3,)。

RobotCommand：下一步要机器人做什么

RobotCommand 是输出命令。它包含目标关节位置、目标速度、前馈力矩和 PD gain。

joint_positions   # target q
joint_velocities  # target dq
joint_torques     # feedforward tau
kp                # position gains
kd                # velocity gains

这也是 safety clamp 的对象：Safety 不改 policy 内部逻辑，而是检查和裁剪 policy 输出的 RobotCommand。

Policy.step：唯一正式策略接口

Policy 基类明确写了 Runtime 只调用这些东西：

step(state, velocity_command) -> RobotCommand
reset()
load(path)
stiffness / damping / default_pos

所以具体 policy 内部可以很复杂，比如构造 observation、跑 ONNX、平滑 action、映射 joint order。但对 Runtime 来说，它只关心一件事：

cmd = self.policy.step(state, vel_cmd)

RobotInterface：sim 和 real 的共同外壳

RobotInterface 定义了 Runtime 能对机器人做什么：

robot.connect()
state = robot.get_state()
robot.send_command(cmd)
robot.step()
robot.reset()

SimRobot.step() 推进 MuJoCo 物理；RealRobot.step() 基本是 no-op，因为硬件自己的 PD loop 在跑。这就是为什么 Runtime 可以用同一套代码跑 sim 和 real。

Runtime.step 里的真实一帧

进入 RUNNING 后，核心路径在 runtime.py:893 附近：

state = self.robot.get_state()
vel_cmd = self._input_manager.get_velocity()
cmd = self.policy.step(state, vel_cmd)
cmd = self.safety.clamp_command(cmd, state)
self.robot.send_command(cmd)
self.robot.step()

你以后调 bug，先问：问题发生在 state 输入、policy 输出、safety 裁剪，还是 robot 后端执行？

检索练习

  2. Policy.step 返回什么类型？
