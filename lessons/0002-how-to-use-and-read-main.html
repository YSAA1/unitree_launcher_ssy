0002 - 怎么使用，以及怎么读 main.py

目标：你不需要一次读完 main.py。你只需要知道当前命令会落到哪个代码块。

先学使用，不先读源码

这个项目的日常操作可以分成三类：仿真调试、无界面验证、日志/真机相关观察。

你要做什么先用什么为什么
看 policy 是否能在 MuJoCo 站稳/动起来 uv run sim --gui --policy ... 最直观，但需要点击窗口并按 Space 启动。
想用页面按钮和速度滑条 uv run sim --viser --policy ... 比 GUI 键盘更明确，适合学习和远程机器。
只想知道能不能跑通 uv run sim --policy ... --steps 500 --no-log headless 会自动启动，反馈更直接。
做更高频 physics 评估 uv run eval --steps 500 --policy ... eval 会把 sim physics 频率强制到 1000 Hz。
分析以前的数据 uv run replay logs/name/ --gui 这是看历史，不会控制机器人。

完整命令表见 命令速查表。

为什么你看到机器人站着不动

GUI 路径调用的是 run_with_viewer()：它启动控制线程，但不自动 safety.start()。所以窗口打开后默认是 IDLE/默认站姿。你要点击 MuJoCo 窗口，然后按 Space。

stance_29dof.onnx 是速度跟踪/站姿类 policy。启动后如果速度命令还是零，它仍然应该站着。按 Up、Down、Left、Right、,、. 才会给速度命令。

beyondmimic_29dof.onnx 是 motion tracking 类 policy。启动后通常不靠方向键，而是按轨迹时间推进。如果按 Space 后终端没有打印 active policy started，优先怀疑窗口没有键盘焦点。

main.py 不要线性读

把 main.py 当成路线图：

代码块你什么时候读作用
run_with_viewer 你用 --gui 时 MuJoCo viewer 主线程 + Runtime 控制线程。
run_headless 没有 --gui/--viser 时 循环调用 runtime.step()，并默认启动 policy。
run_with_viser 你用 --viser 时 浏览器 UI、速度滑条、状态面板。
build_parser 你想知道命令行参数时 定义 mode、默认 config、参数名。
main 前半 你想知道 mode 怎么分流时 mirror/replay 特殊返回，普通路径加载 config 和 robot。
main gantry/zero 分支 只在你用 --gantry 或 --zero 时 特殊实验路径，初学先跳过。
main 正常路径 你跑普通 policy 时 加载 policy、safety、logger、estimator、input、Runtime。
cli_sim/cli_eval/... 你想知道 uv run sim 怎么进来时 pyproject script entrypoint 包装。

三个先验判断

  1. 如果 GUI 站着不动，先按 Space，再给速度命令。
  2. 如果你只想证明 policy 能跑，先用 headless --steps，别先开 GUI。
  3. 如果涉及 real，先停止：它是安全问题，不是学习阶段的普通模式。
